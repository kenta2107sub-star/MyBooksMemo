# 品質・セキュリティルール（.codex/quality-rules.md）

---

## 品質ルール

```
設計書との整合性：
  □ 設計書にないものを実装しない
  □ エラーメッセージ・エラーコードは requirements.md の定義と一致させる
  □ ファイルは architecture.md のディレクトリ構成通りに配置する

実装の進め方：
  □ 一度に1つの変更を行う
  □ テストがFAILしている状態でリファクタリング・デプロイをしない
  □ 同じアプローチで3回失敗したら別の方法を試す
  □ 5つの方法を試して解決しない場合はユーザーにエスカレーションする

コードの品質：
  □ 1ファイル1責務を維持する
  □ Route Handler にビジネスロジックを書かない
  □ デバッグ用ログを本番コードに残さない

ユーザー提示前の品質ゲート：
  □ 実行可能成果物は、プロジェクトタイプに対応する安全な環境で事前検証する
  □ PASS / LIMITED / BLOCKED を判定し、環境・確認項目・証拠・未検証範囲を記録する
  □ BLOCKED の成果物を完成扱いで提示しない

Codex Cloudの品質ゲート：
  □ 設定画面の保存だけでCloud検証済みにしない
  □ UI選択ランタイムとtask内の実測ランタイムを分けて記録する
  □ 標準テストとgit diff --exit-codeが成功するまでCloud検証済みにしない
  □ Cloud taskから外部API・本番サービスを呼ばない
```

---

## セキュリティルール

基本的な禁止事項（APIキーのハードコード禁止・.envのコミット禁止・機密情報のログ出力禁止）は
`~/.codex/AGENTS.md`（グローバル）の「禁止事項」セクションで定義されている。

以下はそれに加えた実装レベルのセキュリティルール：

```
  □ 環境変数は必ず .env.local / .env から読み込む
  □ 認証が必要なエンドポイントには認証チェックを実装する
  □ 外部からの入力は必ずバリデーションする
  □ エラーメッセージにスタックトレースを含めない
  □ Codex CloudのSecretsはsetup script専用とし、agent phase用の環境変数へ移さない
```

### Codex Security ゲート

- 初回リリース前は Phase 7 Step F でコードベース全体を確認する
- Plugin のパッチは自動適用せず、`security_report.md` を判定してから通常の実装フローで修正する
- 検証済みの攻撃経路、Critical / High、認証・認可回避、秘密情報漏えい、任意コード・コマンド実行、
  不正なデータ変更につながる指摘は「要修正」とし、解消するまで Phase 8 へ進まない
- 重大度が低い、または未検証でも現実的な影響を否定できない指摘は「要判断」とし、
  ユーザーが修正または保留を決め、理由を `progress.md` に記録する
- Plugin が利用できない場合はフォールバックレビューを実施し、未実施のまま完了扱いにしない
