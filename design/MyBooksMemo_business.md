# ビジネス・運用ドキュメント

> **プロジェクト名**：MyBooksMemo（読書メモ・言語化トレーニングアプリ）
> **このドキュメントの用途**：コスト試算・運用メモをまとめたビジネス・運用情報。**Claude Codeの実装には不要。**
> **デプロイ形態**：個人利用のみ（開発者本人のiPhoneにXcodeから直接インストール）。将来的にTestFlightで知人へ配布する可能性を軽く含む、軽量版ドキュメント（本格的な市場調査・収益モデル設計・詳細ロードマップは対象外）
> **関連ドキュメント**：
> - `MyBooksMemo_requirements.md`（機能要件・非機能要件）
> - `MyBooksMemo_architecture.md`（技術スタック・システム構成）
> - `MyBooksMemo_setup.md`（開発着手前チェックリスト・各種設定手順）
> - `MyBooksMemo_basic_design.md`（画面仕様・モック実装指示 ※Phase 2で本ファイルの後に作成）

## 1. サービス概要

### サービス名
`MyBooksMemo`（読書メモ・言語化トレーニングアプリ）

### 目的
毎日本を読む習慣がある開発者本人が、読んだ内容を忘れずに振り返れるようにし、自己啓発本などから得た気づきを「自分の日常にどう活かすか」まで言語化する習慣を身につけるためのアプリ。バーコードスキャンで本を登録し、1日1件のメモを記録、AIとの対話で内容を深掘りし、蓄積されたメモ・対話ログから本単位の要約をいつでも作成できる。

### 現在の位置づけ

| 項目 | 内容 |
|---|---|
| 対象フェーズ | Phase 1（MVP）のみ |
| 利用者 | 開発者本人のみ（完全個人利用） |
| 配布方法 | Xcodeから自分のiPhoneへ直接インストール |
| 将来の可能性 | TestFlightで知人にも配布する可能性がある（本格的なApp Store公開・SaaS化は現時点で想定していない） |

---

## 2. 市場でのポジション（簡易）

Phase 1調査の結果、読書記録アプリ（記録・管理が中心）とAIジャーナリングアプリ（内省・対話が中心）の中間に位置する点が本アプリの差別化ポイントである。本の記録機能とAIとの言語化対話を1つのアプリに統合しているサービスは調査時点で見当たらなかった。

> 本ドキュメントは個人利用前提の軽量版のため、詳細な競合比較表・収益モデルは作成しない。

## 3. コスト試算

> 料金・無料枠・決済条件は変更され得る。実際の契約直前に各サービスの公式画面を確認し、費用は画面に表示される日本円額を正とする。

### 3.1 現状（自分のiPhoneへの直接インストールのみ）のコスト

| 項目 | 費用 | 備考 |
|---|---|---|
| Cloudflare Workers（BFF） | 契約直前に確認 | Free枠の利用を想定するが、料金・カード要否・最新上限はCloudflare公式画面を正とする |
| Google Gemini API（`gemini-3.1-flash-lite`） | 契約直前に確認 | 無料枠の利用を想定するが、モデル別の上限と従量課金条件はGoogle公式画面を正とする |
| Xcodeからの直接インストール（Apple Developer Program） | 登録画面に表示される年間登録料（円） | 本計画では有料Apple Developer Teamを使う。登録時にApple公式画面の日本円額を確認する |
| 国立国会図書館サーチAPI | **0円** | 個人・非営利利用は申請不要・無料 |
| **合計** | **未確定** | Apple Developer Programの登録画面と、Cloudflare・Googleの契約条件を確認後に日本円で確定する |

### 3.2 Gemini API無料枠を超過した場合の可能性

Gemini APIの正確なRPM/RPD上限値と単価は、契約中のプランとモデルの最新公式表示を本番設定直前に確認する。429応答時はFR-04・FR-05・FR-09の異常系に従う。

### 3.3 将来TestFlightで知人に配布する場合の追加コスト

| 項目 | 費用 | 備考 |
|---|---|---|
| Apple Developer Program（年間登録） | 登録画面に表示される年間登録料（円） | 現行の実機直接配布で利用する。TestFlight配布でも継続して必要 |

TestFlightでの配布自体（ビルドのアップロード・テスターへの配布）には、Apple Developer Programの年会費以外に追加費用は発生しない。Cloudflare Workers・Gemini APIの利用量は配布人数の増加に応じて増えるが、少人数（数名程度）であれば無料枠の範囲内に収まる見込みが高い（3.2の従量課金の可能性は配布規模が大きくなった場合に再検討する）。

## 4. 運用メモ

### 4.1 日々の利用イメージ

1. 本を読む
2. 読んだ内容についてその日のうちにメモを記録する（1冊につき1日1件）
3. 気が向いたときにAIとの対話で内容を深掘りする（往復上限5回、いつでも終了可）
4. メモがある程度たまった本について、任意のタイミングで「要約を作成する」ボタンを押し、本単位の要約を確認する

メモの記録・閲覧・削除、保存済み対話ログ・要約の閲覧はオフラインで利用できる。AI対話、要約の新規作成・再作成、今日のアドバイス生成・再試行、書誌情報の自動取得にはネットワーク接続が必要。

### 4.2 秘密情報の管理上の注意（要点のみ）

- `GEMINI_API_KEY`はCloudflare Workers側だけに保管し、iOSアプリには一切含めない。`WORKERS_SHARED_SECRET`はWorkersとiOSの無視対象`Secrets.xcconfig`に同じ値を保持する
- `Secrets.xcconfig`・`.dev.vars`は`.gitignore`対象。誤ってGitにコミットしないよう、`git status`で追跡対象になっていないことを都度確認する
- `WORKERS_SHARED_SECRET`を変更する場合は、Cloudflare Workers側（`wrangler secret put`）とiOS側（`Secrets.xcconfig`）を同時に更新する（片方だけ更新すると全リクエストが401になる。architecture.md 10章参照）
- Phase 1の技術調査時に作成した`.env`ファイルは本番の設計では使わない値。中身のAPIキーをメモしたら削除してよい（setup.md記載の通り）

### 4.3 将来TestFlightで配布する場合に検討すべきこと

| 検討事項 | 現時点の結論 |
|---|---|
| Apple Developer Programへの登録 | 配布前に必須（3.3参照）。個人アカウントでの登録でよい |
| 複数人が使う場合のデータ分離 | 現状のSwiftDataによるローカル完結設計のままで問題ない。各自の端末にそれぞれ別々にデータが保存される形になるため、サーバー側でのユーザー管理・データ分離の追加実装は不要 |
| マルチユーザー対応・共有機能 | requirements.md「作らないこと」の通り、引き続きスコープ外（TestFlight配布はあくまで同一アプリを複数端末にインストールする形であり、ユーザー間の共有・ログイン機能を指すものではない） |
| Cloudflare Workers・Gemini APIの利用量増加 | 配布人数が数名程度であれば無料枠内に収まる見込み。人数が増える場合は3.2の従量課金の可能性を再検討する |

## 5. 運用停止フロー

運用を停止する場合は、依存関係の少ないものから順に以下を実施する。

1. Cloudflare Workersのデプロイ済みWorkerを削除する：Cloudflareダッシュボード → Workers & Pages → 対象Workerを選択 → 削除
2. Google AI StudioでGemini APIキーを無効化する：`https://aistudio.google.com/apikey` → 対象キーを削除
3. （TestFlight配布を行っていた場合）App Store Connectでのビルド配布を停止する：App Store Connect → TestFlight → 対象ビルドの配布を終了
4. （TestFlight配布を行っていた場合）Apple Developer Programの年間登録を更新しない（自動更新をオフにする、または期限到来時に更新しない）
5. iPhone本体からアプリを削除する（SwiftDataのローカルデータもあわせて削除される）

> ⚠️ Cloudflare Workersを削除すると、iOSアプリ側からのAI対話・要約生成リクエストはすべて失敗するようになる（NDL APIによる書誌情報取得・メモの記録閲覧・削除はローカル完結のため引き続き動作する）。
